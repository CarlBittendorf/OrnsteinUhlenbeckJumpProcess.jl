Getting started ​

OrnsteinUhlenbeckJumpProcess provides hierarchical Bayesian models for longitudinal data and event probabilities, built with Turing.jl. Fitting a model produces posterior samples for group-level and subject-level parameters, which the package's analysis functions convert into interpretable quantities such as equilibrium means, deviation half-lives, and event reactivity.

This page walks through the core workflow with synthetic data: simulating observations, choosing a model, sampling with NUTS, and cleaning the posterior samples.

Installation ​

The package is not yet registered in the Julia General registry. Install it directly from GitHub:

julia
using Pkg

Pkg.add(url = "https://github.com/CarlBittendorf/OrnsteinUhlenbeckJumpProcess.jl")

If you are working from a local clone, the package can also be developed directly from its path:

julia
pkg> develop /path/to/OrnsteinUhlenbeckJumpProcess

Data conventions ​

All models operate on nodes: each element of the data vectors corresponds to one observation node. Nodes that follow their predecessor in time form a time series, while the first node of each series is drawn from the stationary distribution. Three conventions apply to every model:

  • Observations live on the unit interval (0, 1), regardless of the original rating scale.

  • Time differences are measured in hours and are computed from the preceding node of the same subject.

  • Event magnitudes (jump model) are scaled to , so that the reactivity parameters can be read as percentage points of affect change.

See Models for the full conventions and the likelihood of each model.

Next, we draw observations from a data-generating model with the default priors. Setting z_obs = missing marks the observations as unknown, so that rand samples them along with all other random variables:

using StableRNGs

data = (;

    subject_indices = [1, 1, 1, 2, 2, 2],
    Δt = Δt,
    is_transition = is_transition

generative = OrnsteinUhlenbeckModel(; data..., z_obs = missing)

Choose a model ​

The package provides three models. Choose the one that matches the data:

ModelUse it for
OrnsteinUhlenbeckModelLongitudinal observations with continuous mean-reverting dynamics
OrnsteinUhlenbeckJumpModelLongitudinal observations with measured positive and negative events
EventProbabilityModelBinary event indicators, without a latent time series

Each model is an ordinary Turing model, so the data-generating trick above works for all of them: pass the observations as missing and call rand on the model to sample from the joint prior.

Fitting with NUTS ​

Any Turing-compatible sampler works. The default NUTS sampler is a good starting point for small models:

julia
using Turing

chains = sample(StableRNG(1), model, NUTS(), 200; progress = false);
size(chains)
(200, 33, 1)

For larger models, consider compiling the reverse-mode automatic differentiation and running multiple chains in parallel; see the Analysis workflow and Jump model workflow examples and the README for the recommended setup.

Common configuration choices ​

The workflow usually changes in a few predictable ways:

  • Increase the number of samples, or use MCMCThreads() with several parallel chains, to stabilize the posterior summaries.

  • Compile the automatic differentiation (AutoReverseDiff(; compile = true)) when the number of nodes grows.

  • Pass the event data (M⁺, M⁻, Δτ) to OrnsteinUhlenbeckJumpModel to include measured events.

  • Keep the time unit in hours, so that the reported half-lives are in hours.

Common mistakes ​

A few patterns usually lead to confusion:

  • Passing observations outside the unit interval, which breaks the prior scales and the interpretation of the cleaned parameters.

  • Forgetting that Δt must be 0 at the first node of each series and is measured from the preceding node of the same subject.

  • Marking the first node of a series with is_transition = true, which references a node that has no predecessor.

  • Reading the raw chain columns (*_raw, z_raw) directly instead of using clean_parameters.

  • Mixing up the scales: μ and γ are reported on a 0-100 percentage scale, θ as a half-life in hours, and α⁺, α⁻ as percentage points per unit of impulse magnitude.
